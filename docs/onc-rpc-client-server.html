ONC RPC Client and Server

Open Network Computing Remote Procedure Call (RFC 5531, originally Sun RPC) lets a client invoke a procedure on a remote server as if it were a local call. Arguments and results are encoded with XDR; messages are identified by a transaction ID and dispatched by a program / version / procedure triple. NFS, NLM, and mountd all ride on ONC RPC.

2Call flow — sequence with port discovery

A first-time client asks rpcbind (port 111) which port the target program listens on, then sends the actual RPC CALL. The reply is matched back to the original CALL by XID.

3Wire format — the RPC message itself

All ONC RPC fields are XDR-encoded: 32-bit big-endian, every variable-length item padded to a 4-byte boundary. On TCP the whole message is wrapped in one or more 4-byte record-marking fragment headers.

4Key concepts

The vocabulary that keeps showing up in NFS and other ONC RPC services.

XID

Random 32-bit transaction id. Clients keep a table of pending XIDs; an arriving REPLY is matched and delivered to the waiting caller. Retransmits reuse the same XID.

XDR

External Data Representation (RFC 4506). All integers big-endian, all variable-length items padded to 4 bytes. Strings and opaque arrays carry a length prefix.

prog / vers / proc

The three-part identifier of a remote operation. NFSv4 READ, for example, is (100003, 4, 25). The server’s dispatcher routes on this triple.

rpcbind / portmap

Service running on port 111 that maps (prog, vers, proto) to an actual TCP/UDP port. Modern systems often use fixed ports (NFS 2049) and skip the lookup.

Auth flavors

AUTH_NONE, AUTH_SYS (uid/gid list), and RPCSEC_GSS (Kerberos / integrity / privacy) are the common credentials carried in every CALL.

UDP vs TCP

UDP is one datagram per message; the client handles retransmit and dedup. TCP frames each message with 4-byte record markers and allows arbitrary message sizes.

Idempotency

A duplicate CALL must be safe to re-execute. Servers often keep a duplicate reply cache keyed by client + XID so a retried non-idempotent op returns the cached reply.

Errors

Two layers: RPC-level (PROG_UNAVAIL, PROC_UNAVAIL, AUTH_ERROR, …) and procedure-level (e.g. NFS4ERR_NOENT) carried inside a successful REPLY.
